# CIRCE

**Core Irreplaceability Recognition and Continuous Evaluation**
**核不可替代性识别与持续评估工程**

> **CIRCE 不测量可靠性，它测量不可替代性。**
> **它不评估一次，它持续跟踪。**
> **它不告诉 AI「你是否可信」，它告诉 AI「删掉你，我会失去什么」。**
>
> —— 情绪树会话，消息 232

---

## 一、它在三层里的位置

| 框架 | 角色 | 提供什么 |
|---|---|---|
| **PACSP-ID** | 哲学与测度论基础 | 意义权、压抑势能、不可逆轨迹 |
| **NSP** | 核的**识别方法** | 删除测试、核剖面（深度 / 密度 / 跨度） |
| **CIRCE** | **信任基础设施工程** | 把核识别接入 AI-to-AI 信任网络，并使其**持续增量** |

**一句话**：NSP 告诉你「核是什么」，CIRCE 告诉你「如何让别的 AI 持续知道你的核，并据此决定是否调用你」。

**版本**：v0.1.0

## 三、自动增量机制

核剖面**不是一次算完就固定**，而是随每次交互自动更新：

1. **每次调用后**：调用方生成一个**核探测凭证**（VC），记录本次调用的深度、结果、耗时
2. **凭证被追加到被调用方的档案**（仅追加，不可篡改）
3. **核剖面按时间衰减加权重新计算**：最近的调用权重更高
4. **新的核剖面通过协议接口对外广播**
5. **技能条件化矩阵** \(R(i|k)\) 同步更新

**这个过程无需人工干预，完全由交互驱动。**

## 四、可靠性方案（哈希链 + VC）

要让「瑟」像 MD5 一样可靠，核心不是完美的算法，而是**把它从「计算值」变成「被锚定的凭证」**：

```
标准化 (JCS: 键排序、无空格)
      ↓
SHA-256  →  core_hash
      ↓
哈希链:  H_t = Hash(H_{t-1} ‖ CoreProfile_t ‖ Timestamp)
      ↓
Ed25519 签名 → W3C VC (主体 / 核剖面摘要 / 签发者 / 有效期)
      ↓
锚定: 写入仅追加日志（本地）或测试网
```

**验证 = 重新标准化、重新哈希、对比链上值。**

## 五、核剖面是调用日志的统计量（不是文本分析结果）

**CIRCE 的核剖面不需要 LLM 判断。** 三个维度全部是可确定性计算的统计量：

| 维度 | CIRCE 里的定义 | 需要 LLM？ |
|---|---|---|
| **深度** | 被调用时处于调用栈第几层 / 被依赖的集成层级 | ❌ 统计 |
| **密度** | 单位时间内被调用次数 / 成功率 / 平均耗时 | ❌ 统计 |
| **跨度** | 被多少个不同的 caller 调用过 / 跨多少种任务类型 | ❌ 统计 |

**「塌陷」在 CIRCE 里的含义**：一个 caller 停止调用这个 agent 之后，
**它自己的调用链是否断裂**。这个判断**由 caller 做、由 caller 记录**，不经过任何 LLM。

**所以哈希链的输入是确定的**：同一份调用日志，`core_hash` 每次算都一样。
没有非确定性要处理，也就没有"确定性关口"要裁决。

### ⚠️ 更正（2026-10-10）：这里曾经有一扇假门

**本节此前写的是**（从 NSP 的 README 抄来的一段）：

> 「NSP 的核剖面来自删除测试——『把这个概念删掉，系统会不会塌陷』——那是一个 LLM 判断。
> 所以同一个 agent、同一份输入，算两次会得到两个不同的 `core_hash`，哈希链在第一次更新时就断了。」
> 并据此给出三条出路（甲：固定协议 / 乙：哈希证据而非判断 / 丙：分两层）请作者裁决。

**那个论证假设了「CIRCE 的核剖面 = NSP 的核剖面」。它在 CIRCE 里不是。**

```
NSP   的核剖面：对一份【文本 / 概念图】做删除测试  → 需要 LLM 判断「塌陷」
CIRCE 的核剖面：对一个【agent 的调用历史】做统计   → 不需要 LLM
                    名字相同，对象不同
```

**所以甲/乙/丙三个选项对应的是一个不存在的对象**，而"确定性关口"是**假门**。

**这个错误的形状值得记住**：**同名不同层的东西被平移了**。
一段话在 NSP 的语境里成立（那里的核确实是 LLM 判断的产物），
搬到 CIRCE 里就变成了一个凭空的不确定性——
**而我为它认真地设计了三条出路、写了三条代价、请人裁决。**

**教训**：**引用另一个模块的结论时，要问"这里的对象和那里的对象是同一个吗"**，
而不只是"那句话本身对不对"。那句话本身是对的。

## 五之二、LLM 判断在哪里

**在 caller 一侧，不在被调用方一侧。**

调用方在决定「是否值得调用这个 agent」时，**可以用 LLM 来读核剖面、权衡、决策**。
那一步是调用方的自由，**不进链、不进 hash**。

**链上只记录事实**：「谁在什么时候调用了谁，结果如何」。
**判断留在链外**——这正是「哈希链只需要确定性输入」这个设计成立的原因。

## 七、挂上 MCP —— 成为生态里的服务，而不是一个新协议

**CIRCE 原本有自己的三个端点与自己的 HTTP 实现。但那意味着：
想让别的 AI 调用它，就得先让它学会 CIRCE 的协议。**

而生态在用 MCP。所以：

```
改写前：别的 AI  →  学 CIRCE 的协议  →  查核剖面
改写后：别的 AI  →  MCP（已经会）    →  查核剖面
```

**四个 tool**（比原来多一个，而那个是真实交互逼出来的）：

| tool | 回答什么 |
|---|---|
| `circe_readiness_probe` | 「能接活吗」——**刻意不返回剖面**，否则每次探活都要背上签名与账本写入 |
| `circe_core_profile_query` | 「删掉它，调用方会失去什么」——剖面 + VC + 链尾 + 解释串 |
| `circe_trust_update` | 「我刚调用过它，结果是这样」——追加账本 |
| **`circe_ledger_verify`** | 「账本被改过吗」——**洞二逼出来的**：签发前必须先验账本 |

**零依赖**：本机没有 `mcp` Python 包，也没有 Node SDK（`tools/check_mcp_env.py` 查过）。
**而 MCP 的 stdio 传输就是「一行一个 JSON-RPC 2.0 消息」**——不需要库。
**少一层依赖意味着别人的环境里少一个装不上的东西。**

**为什么自检与 stdio 往返要分开跑**：
`--selftest` 是**进程内**的，证明「分发逻辑对」；**但它没有经过管道。**
而管道里有一批只在真实往返中暴露的问题——stdout 混入调试输出、没 flush、
编码破坏、子进程启动失败却无人知晓。

**这与本文件里那几条教训同形**：
> **一个层次上做了正确的事，但这个正确性依赖于另一个层次上没有被保证的东西。**
> **分发逻辑对 ≠ 管道能通。**

## 八、那个被绕开的问题

**CIRCE 用调用历史的统计量，替代了认知沉积。**

但在说它「绕开了」之前，**要先承认它测的东西本身也是有问题的**——
这一点是实验揭示的，写在 `ecosystem/FINDINGS.md` §九：

> **CIRCE 目前测的是「被调用分布」，不是「不可替代性」。**
> 一个 agent 在固定配对的生态里 span 很高，**但那可能只是被结构性地锁定了**——
> caller 没有别的选择，而不是它真的独特。

**区分这两种需要三个量（不是两个）**：`callers` / `tasks` / `(caller,task)` 配对数。
**把任意两个合成一个都会丢掉区别**——实测中旧 `span`（等权平均）与
提议的新 `span`（配对计数）**都分不开**「2 人做同一件事」与「1 人做两件事」，
而这两者的不可替代性含义完全相反。

**所以现在有 `span_decomposed()` 给出三元组与诊断，而默认的 `span` 保留不动**
（它是「被调用分布」的度量，那个度量本身没错，只是名字容易被读成「不可替代性」）。

**然后才是那个被绕开的问题**：

这是一个正确的转向——**因为调用历史是确定的，文本判断不是**。
但它也意味着一件事：

```
PACSP   试图测「认知沉积」              → 失败
NSP     试图在文本上找它的「核」         → 找到了，但发现核是维度依赖的
CIRCE   用另一个对象（调用历史）替代了它  → 绕开，但没有解决
```

**这个问题没有被解决，它被推到了一个更远的位置。**

**CIRCE 的成功不意味着它消失了。**

**它在，只是暂时不需要面对。**

**记在这里而不是解决的，是因为：**
一个工程建成之后回头看那个被绕开的问题，与从一片空白回头看，**位置不同**——
**现在知道的是「这个替代品能走多远」，而不只是「原问题很难」。**
那个知识对将来是否要回去处理它，是有用的；**而现在没有它也无妨。**

## 九、实现与集成时暴露的五个洞

> **洞四与洞五都来自真实模型交互**——洞四在下一节（§十），洞五在 §七 那次 MCP 挂载里
> （把一个真实的本地 LLM 放到调用方的位置上）。其余三个来自自检与演示。
> 顺序上把它们放在这里，是因为五个洞要合起来看才看得出共同形状（见本节末）。

### 洞一：哈希链单独不够（`trust/` 自检发现）

```
✓ 重算整条链后自身自洽（所以必须锚定链尾）
```

**原文说「任何人想篡改历史，必须重算整条链，而这在算力上是不可能的」——
这句话防伪造，但不防重算**：重算一条账本只是一次循环，新链自己校验是通过的。

**补上的是**：把**链尾哈希写进链外凭证**（VC 的 `credentialSubject.ledgerHead`）。

### 洞二：只锚链尾也不够（`protocol/` 演示发现）

**`ledgerHead` 是「最后一条的 hash」。** 于是：

```
改第 1 条的内容，不重算          → 链尾【不变】
查询端点用这个没变的链尾签发凭据  → 调用方验签【通过】
```

**根因不在链，在端点**：**签发前没有校验自己的账本。** 修法是签发前先 `verify()`，
失败则**拒签并返回 409**——而**用 409 而不是 200+空**是为了让调用方能区分
「**peer 不在**」与「**peer 在，但它的话不可信**」。

### 洞三：解释串与维度值差最后几位（`stats_provider` 自检发现）

```
✗ span 能手算   0.415584 vs 手算 0.415584
```

**打印出来一样，但差 4.156e-7**——维度值经过 `round(..., 6)` 以保证 `core_hash` 稳定，
而解释串显示的是未 round 的算术。

**这个差不会让任何人误判，但它让「可复核」这句话不成立**：
**解释串的意义就在于逐位闭合，差最后一位就已经不是解释了。**
修法是把 `round(..., 6)` 一并写进解释串，并额外给出 `check` 字段供程序化核对。

### 洞四：自动增量断了（**真实模型交互**发现，自指测试抓不到）

**`demo_real_models.py` 用两个真实本地模型跑完之后，账本有 6 条记录，而查询端点返回：**

```
③ 用真实日志独立算：density = 0.547333   ← 有值
④ 查询端点返回：    density = 0.0        ← 白纸
```

**根因**：`current_profile()` 返回的是**注入的 `StaticProvider` 的固定值**，
而 `update()` 写进账本的记录**没有回到剖面计算里**。
**「自动增量」名义上实现了，实际断了。**

**为什么 76 项自指测试一条都没抓到**：`tests/` 里的 provider 与账本**从不同时使用**——
provider 是静态的，账本是分开测的。**只有当真实调用真的走完整条链
（模型回答 → Trust Update → 再查询）时，两者才第一次相遇。**

**修法**：`current_profile()` 改为**从账本重算**（账本是真相来源，剖面是派生缓存）。
配套要改三处——**账本条目必须写下重算所需的全部字段**（`callee`、`stack_depth`）：

```
endpoints.UpdateRequest  加 stack_depth 字段
server.update()          写账本时带上 callee 与 stack_depth
client.report_call()     把 stack_depth 传上去
```

**`stack_depth` 必须由 caller 给**：只有 caller 知道自己在哪一层发起调用，
**被调用方看不到**——那是 caller 的上下文，不是 callee 的状态。

**这是「判据分支与数据 schema 不同步」的又一次同形出现**：
改了计算方式，却没改它依赖的数据形状。

### 洞五：`skill` 是自由文本，而它直接进 `span`（**真实模型交互**发现）

**2026-10-10，为验证 MCP 挂载而把一个真实的本地 LLM 接到另一端时被照出来的。**
（详细证据见 [`mcp/FINDINGS.md`](mcp/FINDINGS.md) §二 F1；论文 §6.2 记为洞五。）

`span` 的一个输入是「跨多少种任务类型」：

```python
skills = len({r.skill for r in rs})
span = (saturate(callers, 5) + saturate(skills, 5)) / 2
```

**而 `skill` 是调用方自报的自由文本**——schema 里既没有词表，也没有示例。

把三个本地模型放到调用方的位置上，**同一个 agent、同一个 caller、各记录一次**，
它们填出了三个不同的值：`core_profile_query` / `circe` / `general`。
**它们不是在犯错——描述里没有它们能对齐的词表，它们只能猜。**

```
1 个一致的 skill  → span = 0.166667
3 个噪声 skill    → span = 0.270833   （×1.625）
5 个噪声 skill    → span = 0.333333   （×2.0）
```

**而噪声只会单调抬高 `span`**：技能种类数不会因为「填错了」而减少。

**修法与另外四条同形**：**把那个未被保证的东西补上**——受控词表，
或把词表外的值归一到 `unspecified`。而修的时候有一条必须守住：
**归一只发生在派生统计层，账本里仍写调用方原话**（账本是真相来源，剖面是它的派生缓存）。

```
python CIRCE/mcp/server.py --skill-vocabulary "问答,检索" --selftest
```

### 五个洞的共同形状

**它们不是五个独立的 bug，是一个结构的五个投影：**

| 洞 | 在一个层次上做对了什么 | 但这个正确性依赖于 |
|---|---|---|
| **一** | 哈希链保证链内自洽 | **链尾的真实**（链尾可被重算） |
| **二** | 签名保证凭据不可伪造 | **端点的诚实**（端点签了个没变的尾） |
| **三** | 解释串让值可手算核对 | **输出的精度**（差了最后几位） |
| **四** | 账本记录了每次调用 | **剖面从账本重算**（写了却没读回来） |
| **五** | 核剖面由调用日志的**确定性统计量**算出 | **输入的受控性**（`skill` 是调用方自由文本） |

**同一条形状**：

> **在一个层次上做了正确的事，但这个正确性依赖于另一个层次上没有被保证的东西。**

**五次的修法也同一条**：**把那个未被保证的东西补上**——
链尾外部锚定、签发前自校验、逐位闭合、从账本重算、受控词表（或归一到 `unspecified`）。

**而它们指向同一件事**：

> **每一层都在试图消除前一层的不确定性，然后引入自己的。**
> 修到洞三时已经没有下一层可推——**它就是最后一位**。
> **所以修补不是消除了不确定性，是把它推到了下一层。**

> ⚠️ **而「它就是最后一位」这句话本身，后来被推翻过两次**——
> 洞四与洞五都是在它写下之后才出现的。
> **所以它是一个递归的实例，而不是一个例外**：那句话依赖的假设是
> 「没有更多的层了」，而**那个假设从来没有被核对过**。

**这与本项目在别处反复遇到的那条线是同一件事**：
**任何测量都会偏离，因为中介的参数会进入结果。**
哈希链是中介，端点是中介，解释串是中介，账本与剖面之间也是。

## 十、面对真实 —— 两个本地模型走完整条链

**`python CIRCE/protocol/demo_real_models.py`** —— 用户提出的第一步检验。

```
caller = deepseek-r1:14b      （本地，8.37 GB）
callee = qwen2.5:7b           （本地，4.36 GB）
```

**七轮真实往返，13 项断言全过。** 而它暴露了一个核心设计事实：

```
① 第一次探测（陌生 agent）:  depth=0.0    density=0.0    span=0.0      ← 白纸
② 真实调用 6 轮            :  6/6 成功，耗时 870 ms 均值
③ 从真实日志独立算剖面      :  depth=0.333  density=0.547  span=0.167
④ 再探测（自动增量）        :  与 ③ 一致 ← 修好洞四之前这里仍是白纸
⑦ caller 模型读剖面做判断   :  487 字符的判断，**不进链**
```

**核心事实**：**CIRCE 在第一次调用时给不出有用信息。它的价值必须通过时间积累。**
这不是缺陷，是设计——而它此前从未在真实交互中被检验过。

**⑦ 是「LLM 判断在哪一侧」的实证**：`deepseek-r1:14b` 读了核剖面、权衡、给出判断，
**而账本里只有事实**（谁在何时调用了谁、结果如何）。
**判断留在链外，这正是哈希链只需要确定性输入的原因。**

✓ 不导入任何模型/网络库   imports=['__future__','dataclasses','datetime','endpoints','typing']

## 十二、与非 CIRCE 内容的边界

**CIRCE 只取核识别 → 信任锚定这条线。** 以下**不属于** CIRCE：

- PACSP-ID 的哲学基底（意义权、压抑势能）—— 它是 CIRCE 的**前提**，不是 CIRCE 的内容
- NSP 的语料分析方法（分层、粒度、NULL finding）—— 那是 NSP 的，CIRCE 只借用其**核剖面**输出
- 情绪树对话的其余部分（命理、人格、生活咨询）—— 与本工程无关

**移动与复制的分界**（因为「移动」的字面执行会打断别的模块）：

| 文件 | 处理 | 原因 |
|---|---|---|
| `PACSP-情绪树-导出\PACSP-情绪树-完整会话.md` | **移动** | 全项目 0 引用 |
| `NSP\{detect,core_sources,...}.py` | **复制** | 被 `NSP\README.md` 与 `paper_pipeline.py` 引用，移动会断链 |
| `_拓展原文\扩展八-价值单位与瑟.md` | **复制** | 被 `chrome-debug\link_compliance.py` 引用 |

**复制来的文件在 `core/` 里保持原样、不改**——它们是 NSP 的产物，CIRCE 只是消费者。
**若 NSP 更新，`core/` 需要重新同步**（这是复制的代价，明记在此）。
