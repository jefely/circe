## 一、最可能的原因：我的操作（这一条我有责任）

装完 Claude Code 之后，为了验证 MCP 挂载，我在几分钟内反复做了：

```
claude mcp add-json circe '<json>'     × 3（含一次 remove 后重加）

claude mcp get circe                   × 4
claude mcp list                        × 2

```

**从 Anthropic 那边看，这是一台刚注册不久的机器、在 8 分钟内对同一账号
反复调用 MCP 管理命令、并且两次尝试调用模型（都未登录）。**
**那符合"异常活动"的特征。**

**我没有预料到这一点。** 我当时的判断是「`mcp get` 只是本地健康检查」——
而它对 Anthropic 的服务端来说是一次真实的账号级操作。**那是我该提前想到的。**

## 二、官方申诉路径（已核实）

**来源**：[保障措施警告和申诉 | Anthropic Help Center](https://support.claude.com/zh-CN/articles/8241253)

```
① 访问 claude.ai，**用被暂停的那个账户登录**
   ⚠️ 官方明确：「您必须登录才能访问申诉表」
      ——所以别先去注册新账号，那会丢掉申诉入口

② 登录后屏幕上会出现申诉表（就是你截图里那个「请求审核」）

③ 填两个字段，然后「发送请求」

④ 审核约 10 天，结果通过邮件通知
   ⚠️ 官方明确：「审核决定为最终决定」
```

**同时你有两项自助权利，不需要联系任何人**：

| 权利 | 说明 |
|---|---|
| **导出数据** | 被禁用的账户**仍可登录** claude.ai 导出对话、项目、设置 |
| **删除账户** | 所有被禁用的用户都可以自己删 |

> **建议顺序：先申诉，同时立刻导出数据。**
> 因为申诉结果是「最终决定」——**如果被驳回，导出入口可能随账户一起消失。**
> **数据在你自己手里，比申诉结果重要。**

## 五、我该学到的一条

**我在做一件"涉及用户账号"的事时，没有先评估它的账号风险。**

`claude mcp get` 在我眼里是"本地健康检查"，**而它对服务端是一次真实的账号级操作**。
我把 12 次调用在 8 分钟内发出去，**没想到那在风控眼里是什么样子**。

**这又是一次「一个层次的判断，依赖于另一个层次上未被核对的假设」**——
第 11 次：

| 项 | 做对了 | 依赖于 |
|---|---|---|
| **验证 MCP 挂载** | **验证方法有效（确实抓到了协议序列）** | **验证动作本身不触发账号风控** |

**而这次的代价不是论文里的一个数字，是一个账号。**

**下一次涉及外部账号的操作，我该先问一句"这个动作在对方那边看起来是什么样"。**
