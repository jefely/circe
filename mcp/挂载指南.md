### 检查 3：VS Code 真的连上了吗

> ⚠️ **本节 2026-10-10 被实测推翻并改写。原文的判据（"唯一判据是 `mcpGateway.log`"）
> 是错的**——完整证据见 [`FINDINGS.md`](FINDINGS.md) §三。

**为什么原来的判据错**：`mcpGateway.log` 只记**网关**的生命周期。
23:00 那次实测里它仍然只有两行，**而 VS Code 已经解析了我们的 `mcp.json`**：

```
renderer.log  [warning] Overwriting mcp server 'circe' from /D:/myproject/.vscode/mcp.json
              with /C:/Users/Administrator/AppData/Roaming/Code/User/mcp.json.     ← 4 条
window1\mcpServer.mcp.config.ws0.circe.log      ← 为 circe 建了服务器槽位（0 字节）
```

**判据要用日志，而日志要读对那一层。**

**而日志仍然不够**：它只证明「建了槽位」。那个日志是 **0 字节**，
而 `server.py` 启动时会往 stderr 写 `[mcp] CIRCE server 启动: ...`——
**0 字节既不等于"起来了但没说话"，也不等于"没起来"，它什么都不能证明。**

**决定性证据是进程树**（已脚本化）：

```bash
python tools/check_vscode_mcp_live.py
```

**而进程树判据本身也需要一个对照组**——这是 2026-10-11 实测补上的，
因为第一版判据把「没有 circe 进程」直接读成了「circe 起不来」：

| 我方进程 | **对照组**：Code.exe 拉起的 python / node 进程 | 判据 | 退出码 |
|---|---|---|---|
| 在跑 `server.py`，祖先是 `Code.exe` | —— | **✓ VS Code 确实启动了我们的服务器**（观察到的，不是推断） | 0 |
| 没有 | **也是零** | **？ 一个 MCP 服务器都没起——这不能说明 circe 有问题** | 5 |
| 没有 | 有别的 | ✗ 这时才真的是它没被起起来（看下面三条原因） | 3 |
| `Code.exe` 没在运行 | —— | **？ 无法判断**——它明说无法判断，不给一个看起来像结论的东西 | 4 |

**为什么「都没有」不等于「circe 有毛病」**：对照组里包含 **Pylance 自带的 MCP 服务器**
——它是内置的、必然有效的。实测 00:05 那次窗口：`Code.exe` 的后代只有
`conhost.exe` 与 `copilot-runtime.exe`，**连 Pylance 的 MCP 服务器也没有进程**
（它的 `mcpServer.*.log` 同样是 0 字节），`views.log` 是空的（MCP 视图没打开过）。

**所以真实成因是「VS Code 在空闲窗口里一个 MCP 服务器都还没起——因为还没被需要」。**
而第一版那句推论依赖一个**没有被核对过**的假设：
「VS Code 会在窗口打开时就把配好的服务器拉起来」。

> ⚠️ 还有一处同类收紧：第一版把对照组定义为「任何非 Chromium 的后代」，
> 于是 `copilot-runtime.exe` 被当成了「别的 MCP 服务器在跑」，判定从「都没起」
> 错推成「别的起了、circe 没起」。**对照组要选得能代表被测对象**——
> Copilot 运行时不是 MCP 服务器。现在只算 `python.exe` / `node.exe`。

**而「都没起」这一步不需要模型、也不碰任何账号就能推进**：

```
Ctrl+Shift+P → 搜 `MCP` → 打开 MCP 服务器列表 → 找到 circe → Start
```

之后再跑一次本脚本；**那时若仍没有 `server.py` 进程，才是真问题。**

**「读了配置却没起服务器」的可能原因**：

1. 该服务器需要**手动批准**：`Ctrl+Shift+P` 搜 `MCP`，看 MCP 视图里 circe 是不是停在待批准
2. 工作区未被信任（状态栏若显示 `Restricted Mode`，工作区级 MCP 不加载）
3. **重复定义**：两处都有 `circe` 时 VS Code 报 `Overwriting`，保留一处再试（见检查 5）
4. 服务器是**按需启动**的：可能要先在 Chat / MCP 视图里碰它一次
